**Authoritative runs (Repository Cleanup A).** `npm test`, `npm run benchmark:modern` and every `npm run <tool>` that runs compiled code go through `npm run build`, which deletes `.build/` first, exactly once (there are no npm lifecycle hooks). `.build/` is disposable compiled output only, never evidence: a compiled test whose source was deleted is gone before `node --test` discovers tests (`tests/build-discipline.test.ts`). Never run two builds or test runs at the same time in one checkout. **Where files belong (Repository Cleanup B2).** Executable test fixtures live under `tests/fixtures/` (the ones copied from historical evidence are listed with their source and sha256 in `tests/fixtures/provenance.json`). Local output, private and public, goes to the gitignored `artifacts/local/`; tools write new evaluation runs to `artifacts/local/evaluations/`. Committed evidence lives under `docs/evaluations/` and enters it only by a deliberate copy; nothing executable reads it. `tests/evaluation-history-isolation.test.ts` fails if a test, production module or tool uses `docs/evaluations/` as a path, except four historical reproduction tools it allowlists (`src/dev/historical/eval-evidence.ts`, `src/dev/historical/shadow-evidence.ts`, `scripts/d09-*.mjs`, `scripts/historical/minor-debt-controller-audit.mjs`; the D09 reflection evidence they use is in `docs/evaluations/d09-reflection/evidence/`).

**Browser checks.** `scripts/browser/*-browser-check.mjs` are offline real-browser checks. Run `npm run build` first, then `node scripts/browser/<name>-browser-check.mjs`. Paths come from `scripts/lib/browser-env.mjs` (repository-relative); Playwright is loaded from `PLAYWRIGHT_MODULE` or the `playwright` package (`NODE_PATH` works), and `CHROMIUM_PATH` optionally names the browser. Screenshots go to `artifacts/local/browser/<check>/`.

## Dev tooling

Repository Cleanup E gave the developer tools purpose folders. Production code (`src/` outside `src/dev/`) never imports `src/dev/` or `scripts/`. `tests/dev-tooling-boundaries.test.ts` enforces the rules below from the TypeScript syntax tree.

| Folder | What lives there | Network |
| --- | --- | --- |
| `src/dev/play.ts` | the CLI play loop (`npm run play`) | live |
| `src/dev/support/` | fixtures and helpers shared by tests and tools (`turn-fixture.ts`, `turn-services.ts`, scene fixtures, corpora) | offline |
| `src/dev/inspect/` | the `inspect:*` commands and other offline inspectors (`audit-authored-data.ts`, `inspect-city.ts`, diagnostics aggregation) | offline, except `inspect-llm.ts` (`inspect:narrator`, `inspect:controller`, `bench:llm`) and `inspect-embedding.ts` (Voyage) |
| `src/dev/benchmark/` | reusable benchmarks (`benchmark:controller`, the retrieval benchmarks) | `benchmark:controller` is live |
| `src/dev/maintenance/` | the playthrough corpus tools and `scan-identity-forks.ts` | offline |
| `src/dev/live/` | the current live certifications (`keep-track-live.ts`, `identity-live-cert.ts`, `person-offer-live-cert.ts`, `narration-facts-commerce-live.ts`, `narration-facts-identity-live.ts`, `scene-state-live-smoke.ts`, `eval-hardening.ts` behind the supported `inspect:turn` diagnostic; its curated-fixture modes, formerly `eval:playthrough`, are deprecated and run only directly) and their shared `support.ts` (session setup, the single transient retry, usage totals, the OpenRouter wire recorder; tested offline by `tests/live-harness-support.test.ts`) | live: spends credits |
| `src/dev/historical/` | finished milestone harnesses, bake-offs and superseded evaluations, kept for reproduction. They still compile, but they are not npm commands and nothing active imports them. A few are still pinned by tests (a frozen allowlist that may only shrink) | mostly live |
| `scripts/` | `clean.mjs`, `check-doc-links.mjs`, `minor-debt-cycle-check.mjs` (the `clean`, `check:docs` and `check:architecture` commands) and `lib/browser-env.mjs` | offline |
| `scripts/browser/` | the offline real-browser checks | offline |
| `scripts/evaluation/` | `casting-trace.mjs` and `minor-debt-offline-guard.mjs` (offline), and the `*-live-smoke.mjs` item, sprite and transfer smokes (live) | mixed |
| `scripts/historical/` | the D09 harnesses and analyzers, bake-off and pilot runners, and the stale `audit-player-travel-authority.mjs` | mostly live |

- **Supported surface.** A tool is active only when an npm script exposes it, a current document tells you to run it, a current test imports it as support, an active tool imports it, or it belongs to a current certification. Everything else is in a `historical/` folder. Run a historical tool directly (`npm run build`, then `node .build/src/dev/historical/<name>.js` or `node scripts/historical/<name>.mjs`); some of them print usage text that still names their removed npm alias.
- **Live versus offline.** `npm test`, `npm run benchmark:modern` and the browser checks never call a provider. Live tools need `NODE_USE_ENV_PROXY=1` and a key (`OPENROUTER_API_KEY=placeholder` inside the sandbox, where the proxy injects auth).
- **Where output goes.** Every active tool writes under `artifacts/local/` (ignored by git) or the OS temp directory. The live certifications keep their scratch saves under `artifacts/local/evaluations/<harness>/`. The one listed exception is `extract:playthrough`, which regenerates `tests/playthrough/curated.json` on purpose. No active tool reads or writes `docs/evaluations/`. Only the four historical reproduction tools listed in `tests/evaluation-history-isolation.test.ts` may read or write there.
- **Archive policy.** `docs/evaluations/` is historical evidence. Nothing is deleted from it silently: reports are not rewritten, unique provider output, referenced screenshots and provenance manifests stay, and duplicates are removed only when nothing references them. The Cleanup E audit is in [`REPOSITORY_CLEANUP_E_DEV_TOOLING_ARCHIVE.md`](evaluations/REPOSITORY_CLEANUP_E_DEV_TOOLING_ARCHIVE.md).

## Player-authorized actions: how to test

- **Heartstone:** explicit-action tests (`explicit-npc-plus-promotion.test.ts`) replaced the semantic oath-matcher tests; prose never promotes.
- **Actual Offer** (`actual-offer-v1.test.ts`, `actual-offer-ui.test.ts`): test separately offer interpretation (goods G, negotiation N, person P, negatives for auction/silver/questions/hypotheticals), UI presentation, identity masking (security regression), acceptance settlement and atomicity, idempotency, persistence (save/load) and browser behavior. Offline browser check: `node scripts/browser/actual-offer-browser-check.mjs` (scripted narrator/controller, zero live calls).
- **Identity:** `foreground-canonical-binding.test.ts`, `person-offer-e2e.test.ts` (spoken price forms, stable subject, Slave NPC on Accept, rename). Live certification harnesses `src/dev/live/identity-live-cert.ts` and `src/dev/live/person-offer-live-cert.ts` spend credits and are never run by `npm test`.
- **Future certification policy.** A transcript-only replay cannot certify player-authorized actions (the frozen 421-turn oracle is historical and is not modified). A future ~100-turn benchmark should be designed against the current architecture with a scripted **action log**: per relevant turn the player input, Narrator response, Controller result, any explicit player action (`accept_trade_offer`, `completeHeartstoneRite`, save/load) and the expected authoritative delta, plus the expected final state. This is a recommendation; it is not built. The historical replay harness (`payment_gap`) still expects in-turn person transfer and needs adapting before it is run again.
